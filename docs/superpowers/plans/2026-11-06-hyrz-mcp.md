# hyrz MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 在 test 提供 hyrz MCP、数字 QQ 绑定/用户 ID 解析及二维码申请/结果工具。
**Architecture:** 新 MCP 复用现有网站业务，数字 QQ 使用独立关联表。网站登录确认一次性链接；可信机器人后台使用服务端 Bearer 密钥调用五个工具。
**Tech Stack:** TypeScript ESM、Express 5、Mastra MCP 2.x、PostgreSQL、现有 Redis/OSS。
**Spec:** `docs/superpowers/specs/2026-11-06-hyrz-mcp-design.md`

## Global Constraints

- `E:/code/NarutoLoginClient`，分支 `test`，不创建 worktree、不推送或部署。
- 保留现有 openid 绑定与网站申请流程。所有提交使用中文。
- Node >=22.13，MCP `/api/mcp`，名称 `hyrz`；密钥仅由可信后台持有。
- 测试不访问真实服务、配置或凭据。

## Review Focus

- 公开链接被其他账号重复确认、并发确认、解绑后旧链接重放，不能接管账号。
- QQ/用户/任务参数不能绕过有效账号、已绑定状态或任务归属检查。
- 旧网页会话/CSRF/原始 QQ 验签入口保持原有行为；MCP 使用独立认证和解析。
- 已扫码、刷新中、过期和同路径替换图片不能错误报告为可扫码成功。
- Mastra HTTP 发现、旧协议调用、生产构建和 Vercel 入口均包含五个工具。

## Task 1: 数字 QQ 服务与确认页面

**Files:** `src/server/mcp-qq-bindings.ts`、`tests/mcp-qq-bindings.test.ts`、`src/frontend/components/mcp-binding-dialog.tsx`、`src/frontend/lib/mcp-bindings.ts`、`src/frontend/App.tsx`。
**Interfaces:** `McpQqBindingService(config, {beforeInitialize, store?, now?})` 提供 `create(qq)`, `preview(token)`, `confirm(userId,token)`, `resolve(qq)`, `unbind(userId)`, `assertActiveUser(userId)`, `close()`。结果对象使用 `qq,userId,bindingUrl,expiresAt,boundAt`，解绑返回 `{userId,status:'unbound'}`。

- [x] 先写测试证明未确认不能解析、确认需有效网站账号、唯一 QQ 冲突/过期/重放与解绑取消挑战、openid 原表不变。
- [x] 用临时 PGlite 和真实 SQL 验证状态和事务；实现只保存令牌摘要的服务。
- [x] 页面读取 `#mcp-bind=<token>`，显示 QQ 与当前网站用户名；未登录引导现有登录，明确点击后确认，不自动确认。
- [x] 验证页面更换账号时清除旧状态，禁用重复提交，错误可读且令牌不写日志。
