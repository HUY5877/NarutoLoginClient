# 网站发码后由新 QQ 机器人完成绑定

用户要求只在 `test` 修改：登录网站后从原 QQ 群提醒入口取得随机字符串，在群里 @ 当前 NapCat 普通 QQ 机器人发送该字符串，机器人用可信消息里的数字 QQ 自动绑定到生成码的网站用户，无需第二次网页登录确认。

## 选择与范围

用户补充明确：本次只完成绑定，旧提醒逻辑不变；新绑定必须独立建表，旧表以后逐步下掉。所有新机器人绑定（包括 `bind_qq` 无代码模式）使用 `qq_robot_bindings`，代码使用 `qq_robot_binding_codes`；不读写、拷贝或自动迁移旧 `qq_number_bindings` / `qq_number_binding_requests` 或官方 OpenID 表。保留 `bind_qq` 名称并新增可选 `bindingCode` 参数：无代码仍直接创建/复用新表用户；有码只绑定到代码所属现有账号，错误代码绝不降级创建新账号。数据库只保存代码摘要。

新增登录保护的 `/api/qq-number-binding`：GET 返回 `{enabled,binding:{qq,boundAt}|null,challenge:{id,expiresAt}|null}`；POST `/challenge` 空请求体生成 `{id,code,expiresAt}`；DELETE 解除当前用户的数字 QQ 关联。网站 Cookie 决定用户，不接受正文 userId。代码为 18 个随机字节的 base64url 字符串（24 字符），有效 5 分钟，重发废止旧码；状态接口不返回明文。

新表兑换与绑定使用独立跨进程事务写锁。QQ 若已在新表关联自动创建的账号，兑换时转到代码所属已登录网站账号，保留被转出账号及历史。目标账号在新表原有其他 QQ 时也只在兑换成功时替换。代码成功后只允许同一 QQ 在实际关联与 boundAt 未变时幂等重试；其他 QQ、过期、解绑、转绑、重新发码均不能重放。成功兑换只撤销新表关联代码，停用目标不允许兑换。旧绑定和旧确认链接独立保留，不会覆盖新表。

前端原入口改为“QQ 机器人绑定”，指引从 QQ 的 @ 列表选择当前机器人（QQ 3470367045），粘贴 `绑定 <code>`。轮询显示 QQ 与绑定成功，移除网页确认按钮；保留倒计时、重发、解除、错误、关闭/切换用户隔离。页面准确说明这是数字 QQ 与网站账号关联，不声称已经迁移了任务提醒发送。
