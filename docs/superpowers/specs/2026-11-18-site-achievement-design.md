# 全站累计游戏成就

用户要求在 `test` 合入 `main` 后，为网站增加炫酷的成就提示，合并日常与决斗场周胜次数，不记录访问量。

## 设计

- 展示全站成功完成的游戏任务总数，每次日常或周胜执行完成记 1 次。失败、中断、仅生成二维码不计；周胜按一次任务计算，不按单局战斗计算。
- 用金色徽章、发光数字、轻微流光与现有紫黑村落背景结合；移动端紧凑，支持减少动态效果。
- 公共只读接口 `GET /api/achievements` 返回 `{ totalCompleted: number }`，不返回账号或任务明细。加载、异常与真实零次分开显示。
- 页面每分钟及重新聚焦时更新，后台标签页停止轮询。

## 方案选择

数据库现有申请数量不能证明游戏已完成；网页观察任务状态会漏掉关闭页面后的完成。采用 worker 权威完成状态写入时原子累计、网站只读的方案。

Redis Hash `${REDIS_QUEUE_KEY}:achievements:completed` 保存 `daily` 和 `arena_weekly`，不设置 TTL。任务记录保存 `completedAchievementCounted`，结合已有 worker / attempt / 终态校验防止重试重复计数。统计随现有测试/正式队列前缀隔离，依赖 Redis 本身的持久化与备份。

## 历史与部署

这是实现时确定的口径：旧记录不含完整的永久成功历史，不将申请数冒充完成数，也不补造历史。新版 worker 启用后开始累计，页面说明“自成就功能上线起累计”。需同时部署网站与 worker 的 `test` 分支。
